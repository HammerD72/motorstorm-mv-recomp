`threshold_scan.cpp` operates on typed float records and four thresholds. It reduces
complete records once, handles partial cyclic views, and retains an already-set
failure flag. The game adapter marshals the ABI and preserves every scratch lane;
the core contains no guest registers, opcodes, dispatch or scheduler operations.
The verified span is LS `0x12338..0x12400`: r6/r84 supply aligned begin/end,
r10's preferred offset is 44, r11 supplies four thresholds and r8 holds the flags.
Each back edge scans eight components in 50 original instructions. The adapter
materializes all lanes of r2/r4/r5/r6/r7/r8/r9/r15 and the last policy PC; it writes
no LS memory. Other offsets, wrapping extents and oversized input remain original.

interpretation policy remains required. The generic fork-native-leaf seam is reused;
this change adds no toolkit title exception or scheduler tuning.
Enabled interrupts are admitted only for synchronous list-stall notification, with
no parked list; the exact span has no channel operations that could raise it.
Other unmasked sources retain instruction-level execution even when not yet pending.
Expected unsupported inputs use the typed core's `noexcept` optional-result API;
the adapter declines visibly without allocating or unwinding a C++ exception. The
throwing API remains available for callers that treat invalid inputs as errors.

before generating an ignored guard. It preserves occupied/modified outputs and

## World transforms

[`world_transforms.h`](../src/motorstorm/world_transforms.h) defines caller-owned host matrices, parent indices, root indices and dirty flags. [`world_transforms.cpp`](../src/motorstorm/world_transforms.cpp) evaluates the operation directly on x86, without guest registers, local-store access or instruction dispatch. Parents precede children. A root's translation is restored after the relative hierarchy composition. CPU-only translation scratch is outside this interface.

Compile this operation separately with AVX2/FMA and strict floating-point behavior. Its paired fused products use toward-zero rounding and flush subnormal results. The complete caller MXCSR is restored on normal and exceptional exits. Parent/root ownership, non-finite inputs and arithmetic range violations throw. Callers must use pending host outputs and discard them on failure; the kernel does not provide a transaction over caller buffers. A production adapter must check host instruction support before entering this compiled operation.

Run `python scripts/check_native_world_transforms.py` on an x86-64 AVX2/FMA host with a C++ compiler. Windows accepts `MV_CLANG`; other hosts accept `CXX`. The authored fixture checks independent rounding, fusion, rotation, translation, roots, dirty flags, rejected inputs and caller FP state. A deliberately wrong-rounding implementation must fail the independent product oracle. Build products remain under ignored `build/self-tests/`.

Run `python scripts/check_native_world_properties.py` for the separate
[independent forest properties](NATIVE_WORLD_PROPERTIES.md): 512 fixed-seed forests,
alternate valid orderings, an exact integer point oracle, dirty/no-op/input/FP-state
checks, minimized reproducers and two implementation mutants. This finite-domain
gate complements the dedicated rounding/fusion tests; it does not establish SPU
equivalence, runtime integration or a measured speedup.

## Cooperative job dependencies

[Issue 183](https://github.com/robbe1912/motorstorm-mv-recomp/issues/183) owns the native job-marker wait. [`job_wait.h`](../src/motorstorm/job_wait.h) describes a progress source with a claimed-job count and six active lanes. The operation resolves ownership on every poll, reads the claimed count before a full barrier, scans every lane, and returns only when their unsigned minimum reaches the marker. This ordering follows the original instructions; the old decompiler pseudocode placed the barrier differently.

[`job_wait_adapter.cpp`](../src/motorstorm/job_wait_adapter.cpp) reads real producer counters and preserves the actual AOT return register/condition state. It performs no guest writes before completion. Short waits poll briefly; blocked work then uses a per-thread high-resolution Windows timer or a host sleep on other platforms. Unsupported inputs or timer failures visibly execute the retained original operation. There is no fabricated completion or synthetic timeout. `MS_NATIVE_JOB_WAIT=0` selects the original operation in the bound binary; it does not disable native hierarchy work.

Set `MS_NATIVE_JOB_WAIT_PROFILE=1` to time native waits without suspending threads. It is off by default; disabled/reference calls read no profiling clock. Each `[NATIVE_JOB_WAIT_PROFILE] status=complete` record reports the host thread, original return address (`caller`), list object, returned owner, requested marker, completed minimum, poll/cooperation counts and integer `started`, `finished`, `frequency`, `ticks` clock fields. Windows uses raw QPC; other platforms use steady-clock nanoseconds. Clock failures, changed/zero frequency or backward readings emit `status=clock_error` without a duration; completed work is never rerun because a measurement failed. `original` and `reference` statuses identify unmeasured retained execution. Group only validated records with a common clock and explicit observation window. Wait latency includes cooperation and producer scheduling; it is not exclusive CPU time or displayed FPS. Log emission also perturbs execution. Verify caller edges against the selected original before naming a producer. [Issue 188](https://github.com/robbe1912/motorstorm-mv-recomp/issues/188) owns native validation of this diagnostic.
