# Native game operations

[Issue 177](https://github.com/robbe1912/motorstorm-mv-recomp/issues/177) owns native scene-hierarchy integration. [Issue 27](https://github.com/robbe1912/motorstorm-mv-recomp/issues/27) owns sustained 30 FPS acceptance. The public kernel, scene adapter and verified build binding are implemented and have run through observed normal PLAY.

## World transforms

[`world_transforms.h`](../src/motorstorm/world_transforms.h) defines caller-owned host matrices, parent indices, root indices and dirty flags. [`world_transforms.cpp`](../src/motorstorm/world_transforms.cpp) evaluates the operation directly on x86, without guest registers, local-store access or instruction dispatch. Parents precede children. A root's translation is restored after the relative hierarchy composition. CPU-only translation scratch is outside this interface.

Compile this operation separately with AVX2/FMA and strict floating-point behavior. Its paired fused products use toward-zero rounding and flush subnormal results. The complete caller MXCSR is restored on normal and exceptional exits. Parent/root ownership, non-finite inputs and arithmetic range violations throw. Callers must use pending host outputs and discard them on failure; the kernel does not provide a transaction over caller buffers. A production adapter must check host instruction support before entering this compiled operation.

Run `python scripts/check_native_world_transforms.py` on an x86-64 AVX2/FMA host with a C++ compiler. Windows accepts `MV_CLANG`; other hosts accept `CXX`. The authored fixture checks independent rounding, fusion, rotation, translation, roots, dirty flags, rejected inputs and caller FP state. A deliberately wrong-rounding implementation must fail the independent product oracle. Build products remain under ignored `build/self-tests/`.

## Build and scene bridge

`python scripts/project.py build --optimize --jobs 1` enables native hierarchy binding by default for the verified original debug-US ELF. `--no-native-world-transforms` retains the unbound reference build. Direct CMake configuration uses `PORT_NATIVE_WORLD_TRANSFORMS=ON` and `PORT_TARGET_ELF` pointing to the selected original ELF. This does not change the required PM interpretation for unreplaced work.

[`native_game_binding.py`](../scripts/native_game_binding.py) verifies the original ELF and recovered reference-body identities, copies the selected generated tree into the build directory, and renames only the copied reference definition. A generated forwarding entry preserves direct callers and the registration table; registry-only replacement would miss direct calls. Other translation units retain their source paths and commands. Changed identities, stale copies and reparse points fail preparation. Original inputs remain read-only. The accepted identities are deliberately narrow; another target or changed generated reference needs verification before its binding is added.

[`scene_hierarchy.cpp`](../src/motorstorm/scene_hierarchy.cpp) converts active, dirty hierarchy inputs into pending host buffers. It checks list/object/layout/data ownership and buffer overlaps before committing world matrices and dirty flags. Inactive, clean and empty work avoids unnecessary matrix access. Topology-dirty or unsupported numeric inputs visibly execute the retained original operation before any native guest writes. The adapter does not change root indices, CPU-only translation scratch, job markers or the original implementation flag. This synchronous game operation replaces its original submission and wait for supported work.

[`native_cpu.cpp`](../src/motorstorm/native_cpu.cpp) is compiled without AVX flags and checks AVX2/FMA, XSAVE/OSXSAVE and enabled XMM/YMM OS state before entering the separately compiled kernel. Unsupported hosts retain original execution. `MS_NATIVE_HIERARCHY=0` selects that reference path in a bound build; `1` enables native work, which is the bound default. Native-operation counters and visible fallback records describe coverage; they are not FPS measurements.

Run `python scripts/check_native_game_binding.py` and `python scripts/check_native_scene.py` for authored binding/transaction tests. They verify unchanged originals and direct/table callers, stable repeated preparation, wrong identities and junction rejection, native commits, whole-list fallback without partial writes, CPU/OS capability requirements, context/FP preservation and reference mode. A bad-commit mutant must fail the independently expected world result.

## Runtime evidence and remaining coverage

The private original-work shadow run `20261021T155524.955563Z` compared 3,744 hierarchy snapshots / 18,896 nodes from 936 objects. World bits, roots, scratch, flags, inputs and layouts matched exactly, without tolerances. It covered 900 dirty snapshots and no topology-dirty snapshots. The public kernel independently replayed the same inputs against original job outputs with zero differences.

An opt-in private adapter then ran the public kernel through normal PLAY in native DX12 run `20261021T162204.182417Z`, executable SHA256 `f2291c150bc49e73d9177677995805db8efed5ba406ca9a37c3bdb9b47aba26b`. Original menu assets and the racing HUD were internally observed. The last cumulative checkpoint recorded 20,224 native operations and 2,699,314 nodes, with 16 visible numeric-range fallbacks to unchanged original work. This does not establish topology-dirty gameplay parity or complete interpreter removal. The adapter computes and validates pending outputs before guest writes; it does not change job markers or the game's implementation flag.

This diagnostic is not a controlled speed comparison. Its late Present API interval median was 553.151 ms; that is not displayed or simulation FPS. Stable 30 FPS remains unachieved. Raw inputs, outputs, captures, original code and provenance manifests stay private outside disposable run retention. The next integration must retain the original path for uncovered inputs, preserve observable diagnostics, and identify the remaining critical wait using matched native symbols.

Matched-PDB main/all-thread sampling succeeded for ten seconds each. The main capture contained vehicle-completion and PVS-visibility marker waits, CPU-surface readback waits and flip waits. Sampling includes waits and perturbs execution; this is a lead for issue 155, not exclusive frame-time attribution or a controlled speedup.
